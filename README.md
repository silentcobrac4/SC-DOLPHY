# SC DOLPHY

أداة أبحاث بروتوكولات لاسلكية لأندرويد (NFC, BLE, IR, شبكة) بدون الحاجة لصلاحية Root.

التطبيق مستوحى من مشروع [Dolphy](https://github.com/unvoiddd/Dolphy-App) مفتوح المصدر (GPL-3.0)، لكنه **مكتوب بالكامل من الصفر** بدون نسخ أي كود منه. تم استبعاد عمدًا كل ميزات التشويش/الهجوم الموجودة في المشروع الأصلي (IR Jammer، Bluetooth Jammer، محاكاة Wi-Fi DoS، كسر كلمات مرور Wi-Fi) لأنها أدوات تستهدف تعطيل أو اختراق أجهزة أخرى دون إذن.

## الميزات

### من النطاق الآمن للتطبيق المرجعي
- **IR**: قاعدة بيانات ريموتات لأجهزة شائعة (TV/AC/بروجكتور) وإرسال إشارات عبر `ConsumerIrManager`.
- **NFC**: قراءة وكتابة وسوم NDEF، مع تفاصيل موسّعة لأنواع الشرائح (MIFARE Classic, NTAG/Ultralight, FeliCa).
- **QR**: توليد أكواد QR، ومسحها عبر الكاميرا (CameraX + ML Kit).
- **BLE**: ماسح عام لأجهزة BLE (الاسم، RSSI، الخدمات)، وماسح مخصص لأجهزة الصوت المقترنة.
- **HID**: محاكاة أساسية للوحة مفاتيح بلوتوث عبر `BluetoothHidDevice` (نسخة إثبات مفهوم بأزرار محدودة، قابلة للتوسيع).
- **LAN Scanner**: اكتشاف أجهزة الشبكة المحلية (ping + جدول ARP) — اكتشاف فقط، بدون أي حزم هجومية.
- **البث للتلفاز**: زر Chromecast (Google Cast SDK) + اكتشاف أجهزة DLNA/UPnP عبر SSDP.

### الميزات الأصلية الإضافية
1. **محلل البروتوكولات**: يلتقط تلقائيًا حزم BLE ووسوم NFC أثناء استخدام تلك الوحدات، ويعرضها بصيغة Hex، مع تصدير CSV/JSON.
2. **Dolphy Chat+**: دردشة محلية عبر BLE بتشفير **AES-256-GCM من طرف إلى طرف** (مفتاح مُشتق من كلمة سر يتفق عليها الطرفان مسبقًا). دور "استضافة" (Host/Peripheral) ودور "انضمام" (Join/Central).
3. **الماسح الشبكي الذكي**: خريطة بصرية دائرية لأجهزة الشبكة، تصنيف تلقائي (راوتر/كاميرا/IoT/هاتف-حاسوب) بالاعتماد على اسم الشركة المصنّعة (OUI) واسم المضيف، وتنبيه فوري عند ظهور جهاز جديد غير مسجّل سابقًا.
4. **قراءة NFC موسّعة**: تفاصيل إضافية لأنواع الشرائح الشائعة (MIFARE Classic/Ultralight, FeliCa System Code/Manufacturer).

## حدود معروفة
- **HID**: النسخة الحالية تدعم عددًا محدودًا من المفاتيح كمثال عملي (A، مسافة، Enter، حذف). يمكن توسيعها لاحقًا لدعم لوحة مفاتيح كاملة ووضع ماوس.
- **قاعدة ريموتات IR**: تغطي إشارات "تشغيل/إيقاف" أساسية لعلامات شائعة (بروتوكول NEC). ريموتات نادرة أو بروتوكولات غير NEC تحتاج توسيعًا لاحقًا.
- **قاعدة بيانات OUI**: مجموعة فرعية عملية من الشركات الشائعة، وليست قاعدة IEEE الكاملة.
- **التطبيق غير موقّع بمفتاح توزيع خاص** — يُبنى بتوقيع Android الافتراضي للإصدار التجريبي. لإصدار رسمي موزّع، يجب إعداد keystore خاص وأسرار توقيع في GitHub Actions لاحقًا (غير مُضمّن هنا).
- لم يُختبر بناء Gradle محليًا داخل بيئة إعداد هذا المشروع (لا تتوفر شبكة لتحميل التبعيات هنا)؛ سيقوم GitHub Actions بمحاولة البناء الفعلي عند الرفع.

## طريقة البناء عبر GitHub Actions

1. أنشئ مستودع GitHub جديد (فارغ).
2. ارفع ملف `app-source.zip` المرفق إلى **جذر** المستودع كما هو (لا تفك ضغطه).
3. ارفع أيضًا مجلد `.github/workflows/build-release.yml` (أو استخدم النسخة المستقلة المرفقة بنفس الاسم) إلى نفس المسار `.github/workflows/build-release.yml` في المستودع.
4. من تبويب **Actions** في GitHub، شغّل الـ workflow يدويًا (Run workflow)، أو أنشئ وادفع tag يبدأ بـ `v` (مثل `v1.0.0`) لتشغيله تلقائيًا ونشر Release.
5. بعد نجاح البناء:
   - ستجد ملف APK في **Actions → Artifacts** (لأي تشغيل).
   - إذا كان التشغيل عبر tag، سيُنشأ **GitHub Release** تلقائيًا يحتوي على APK.

> لن يُنشأ أي Release قبل نجاح البناء فعليًا، ولن يُقال إن النشر تم إلا بعد نجاح الـ workflow بالفعل.

## البناء محليًا (اختياري)

```bash
unzip app-source.zip
cd sc-dolphy
gradle wrapper --gradle-version 8.7   # إن لم يعمل gradlew المرفق مباشرة
./gradlew assembleRelease
```
APK الناتج يكون في: `app/build/outputs/apk/release/`
